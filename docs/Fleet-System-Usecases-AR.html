الأسطول والمركبات

9 حالات
ملف السيارة/Vehicle/{id}

بطاقة غنية + تاريخ الخدمة + جسر الربحية (إجمالي←صافي) لكل مركبة.

تدرّج الحالة البصريCondition Grade

أخضر/برتقالي/أصفر/أحمر (افتراضي أخضر). الأحمر يُجمِّد ويُخفى من المتاح؛ البرتقالي/الأصفر يبقى قابلاً للتأجير مع إقرار موثَّق.

خط الأساس العالمي للممشى

عدّاد ذاتي التصحيح مرتكز لأقدم قراءة عقد + فحوص شذوذ (rollback/jump) عبر mileage:scan.

تدقيق سلسلة الممشى/mileage-chain-audit

تسليم العداد من عقد لعقد (تطابق/عدم تطابق/مفقود) + تصحيح سريع غير هدّام.

مصادر بيانات التسجيل

API يملك التأمين، وشيت التأمين يملك الملكية/الرهن، وشيت RTA يملك المخالفات/الحالة.

مفتاح هوية الأسطول

تعريف سياراتنا عبر CarOwnerNo لا TrafficID (المشترك بين 60+ مالكاً).

مقارنة السيارات: شيت ↔ API

القائمة المرجعية من تبويب «Faster» تُطابَق بالـ VIN لصفحات المقارنة والإثراء.

قاعدة مصدر السيارات

الـ API هو المصدر الوحيد لوجود السيارة؛ الشيت يُثري المتطابق فقط ولا يخلق سيارات وهمية.

مصدر سعر الشراء

شيت الأصول (FASTER) مصدر وحيد لسعر/تاريخ الشراء، يُوصل بالـ VIN؛ الشيت يفوز عند وجود قيمة والفراغ لا يمسح.

العقود والتأجير والعملاء

6 حالات
فهرس العقود/contracts

C إيجار / R حجز / U صيانة، مع فلاتر الحالة والرصيد والبحث.

بوابة الحجز حسب الحالة ✅

الأحمر يُمنع؛ البرتقالي/الأصفر يتطلّب إقراراً موثَّقاً على العقد (condition_ack_*) — منفَّذة فعلاً.

محفظة العميلWallet

رصيد مدفوع مُرحَّل من عقود سابقة يُطبَّق تلقائياً على العقد الجديد.

تبديل العقود / تبادل السيارات

سلاسل تبديل السيارة (parent_contract_id)، كشف ±48 ساعة، حمل رصيد تسجيلي، حارس عميل وهمي.

الفوترة — فواتير ومدفوعات

فواتير يدوية M- ومدفوعات P- على أي عقد؛ الرصيد = المفوتر − المدفوع، مع حارس مزامنة OM.

إثراء أسماء العملاء

مزامنة الأسماء بالجملة من endpoint قائمة OM لحلّ العملاء بلا أسماء.

الصيانة — الأساسيات والبيانات

9 حالات
لوحة الصيانة/maintenance

حالة الإصلاح/الكراج/الأعطال/الأولوية من آخر حدث لكل سيارة في سجل شيت N-Maintenance.

عقود الصيانة (النوع U)

بنود الفاتورة، المورّد، ووسوم الأعطال لكل زيارة ورشة.

معمارية بيانات الصيانة

شيت N-Maintenance أساسي، مملوك أيضاً بأحداث ورشة يدوية؛ مرجعية MAIN→Reason.

تسوية الإرجاع/maintenance-returns

الشيت يظهر رجوع السيارة بينما عقد الصيانة ما زال مفتوحاً — سطح لإقفاله.

قاعدة ربط العقد ↔ الصيانة

مطابقة صارمة (سيارة + نافذة تاريخ)؛ IN=رجعت، بلا تطابق=«No Log» — تقتل الفوات الوهمي على اللوحة.

الصيانة أثناء الإيجار

«الإيجار هو الملك»: تداخل صيانة∩إيجار وقتُ إيجار؛ أيام الورشة = الصيانة − الإيجار. لا حظر ولا مخالفات.

حالات العملاءCustomer Cases

تبويب ثانٍ يُستورد كأصل customer-sheet (عناوينه مضلِّلة، يُخرَّط بالمحتوى).

تنبؤ الصيانة/maintenance-foresight

التقاط السيارات قبل العطل (خدمة/مزمن/بطارية) + محاكاة التوقّف وانتظار القطع وكلفة التقاعس.

فاصل خدمة الزيتOil Change

فاصل الكيلومترات لكل سيارة (VALIDITY) من تبويب مخصص، والباقي من الـ API.

محرك سير عمل الصيانة (التذاكر)

18 حالة
محرك سير عمل الصيانة/maintenance-tickets

دورة حياة التذكرة (مفتّش→مشرف→سائق→كراج→إعادة فحص) بدل الواتساب، مع فصل الصلاحيات.

إنشاء/تعديل/حذف أحداث الورشة

صفوف صيانة من الموقع (origin=manual)؛ كلمة مفتاحية→حالة؛ مزامنة الشيت اختيارية.

كتالوج الأعطالFindings

مكتبة كلمات مفتاحية مركزية + FindingsPicker (اختيار متعدد + مخصص) في خطوتَي الاختبار والكراج.

تدقيق أحداث سجل السيارة

جدول vehicle_log_events: كل انتقال يُسجَّل، منفصلاً عن الصيانة حتى لا يوجد ازدواج تكلفة.

تفويض المشرفDelegation

المشرف يفوّض سائقاً (يعيد استخدام assigned_driver_id) عبر maintenance.delegate.

درجة خطورة العطلFault Severity

تصنيف تشخيصي إلزامي للمفتّش (🔴/🟡/🟢) في خطوة القرار + شارة وفلتر على اللوحة.

طبقة إعادة الفحص QC

الفشل يُرجع السيارة للمشرف (لا لنفس الكراج) بشارة لوم الكراج + حالة reinspection_failed.

قواعد استمرارية العداد

تفاوت +5كم، حكم لكل مرحلة (موثَّق/تباين/اختبار قيادة) عبر OdometerContinuityService.

استقبال الشكاوىComplaint

العمليات تسجّل شكوى عميل ← تذكرة تُولد مباشرة في inspection_pending، وتُنبِّه المشرفين والمفتّش.

تحليلات أداء الصيانة

زمن لكل عطل، كلفة مؤجلة (الإقفال بلا تكلفة)، ومراقب الأعطال المزمنة.

تشخيص العَرَض ← السبب الجذري

قاعدة معرفة fault_causes + RootCausePicker إلزامي لكل عَرَض؛ الأسباب المخصصة تُعلَّق للمشرف.

نموذج حاوية المهام

التذكرة حاوية maintenance_tasks لكل عطل، لكن كراج واحد؛ routeTicketToGarage يوزّع الكل.

بوابة ضمان الجودةQA gate

الإصلاحات المعقدة: حالة pending_qa وجولات اختبار (صورة عداد + نجاح/فشل)، ومؤشر «أيام في QA».

بوابة مراجعة فيديو المشرف

حالة repair_review: رفع فيديو أدلة الكراج (maintenance_media) + موافقة→QA / طلب إعادة→كراج.

بنود الصيانة (قطع + عمالة)

أسطر قطع/عمالة (كمية×سعر)، ضمان/متانة (installed_on+أشهر)، جاهزة لأودو؛ جمع تلقائي للتكلفة.

مكتبة مخاطر الكلمات/finding-keywords

إدارة كلمات الأعطال (config→DB) بمخاطر لكل كلمة (🔴/🟡/🟢).

ملاحظة صيانة قديمة تلقائية

إقفال التذكرة يولّد ملخصاً بصيغة السجل القديمة من خطوات التذكرة، يظهر في كل واجهات التاريخ.

الزمن في المرحلةTime-in-Stage

بطاقات اللوحة تعرض زمن المرحلة الحالية + تنبيه SLA أحمر (انتظار توزيع >4س) عبر last_state_change_at.

لوحة تبديل الصيانة/maintenance-swap

كانبان: تعيين سيارة بديلة حين تحتاج سيارة مؤجَّرة الورشة (جدول maintenance_swaps).

اللوجستيك وحركة المركبات

5 حالات
توزيع اللوجستيك/logistics

توجيه سيارة لوجهة، إشعار «طابور مهامي» للمُكلَّف، وشبكة تعرض «قيد النقل إلى X».

اللوجستيك كمصدر وحيدCanonical

LogisticsTask المكان الوحيد لكل حركات المركبة + «أين السيارة؟» (ping/reply).

دورة المطالبة ذهاب-إياب

dispatched→en_route→picked_up→delivered→returned؛ استلام GPS + صور عداد قبل/بعد إلزامية لرحلات الكراج.

الموقع الحيّ الموحّد

التذكرة تُبلّغ موقع السيارة الحيّ (🚚 قيد النقل / 🔧 في الورشة) من الحالة + الكراج + الحركة النشطة.

لوحة حضور الفريق/team-presence

«مَن أين»: متاح/مشغول لكل شخص + السبب (نقل/صيانة/فحص)، مشتقّ من العمل المملوك لا الحضور.

المالية والربحية

6 حالات
محرك صافي الربح الحقيقي

يعكس دخل OM المبهم (إيجار+كم+سائق إضافي+بنزين+Cardoo)، وعلَم «العائد السلبي» على التنبؤ ولوحة القيادة.

التسوية المالية/financial-reconciliation

جسر العقود إلى API المحاسبة (سندات ترويسة فقط)؛ صافي ربح لكل عقد وشهري للأسطول (للقراءة فقط).

التعارضات المالية/financial-conflicts

مركز تنظيف الفواتير المكسورة فقط (حساب VAT، تعارض فاتورة↔عقد، ازدواج فوترة).

تكامل ماليات الفواتير

صافي هامش لكل سيارة على /maintenance (دخل R بلا VAT − كلفة الصيانة) + فحص شذوذ تاريخ الفوترة.

سجل الخدمة وفصل الماليات

رفع الفاتورة كسجل خدمة فني بلا أموال؛ كل واجهات المال مخفية خلف علَم SHOW_FINANCIALS.

مرساة بدء الخدمةIn-Service

نسبة الأداء مرتكزة لتاريخ أول إيجار لا الشراء؛ بلا إيجار = «بانتظار الخدمة».

المزامنة والبيانات والتنبيهات

10 حالات
مصدر OfficeManager API

الـ API هو المصدر الوحيد للعقود الآن؛ الشيتات تقاعدت.

استراتيجية مزامنة العقود

فلاتر OM (status_no، OutDate فقط)؛ مزامنة كل المفتوح + آخر 3 أشهر مغلق + كشف الإغلاق.

مشغّل المزامنة CLI

sync-fleet: حراس لكل مرحلة (fleet:refresh، om:sync) + ملخص ودلالات رمز الخروج.

إعادة استيراد مضبوطة

إعادة استيراد OM محمية بنسخة احتياطية (--from/--to/--dry-run + مُدقِّق الزومبي).

قاعدة البيانات والنسخ الاحتياطي

القاعدة الحيّة MySQL «laravel» عبر XAMPP؛ php artisan db:backup.

تدقيق المزامنة والتصحيح التلقائي/sync-audit

«خلاصة تغييرات»: بطاقات عقود جديدة + فروق حقلية was→now؛ يمسح القيم القديمة العالقة.

التنبيهات الفوريةNotifications

جرس داخل التطبيق: إشعارات DB، polling، كواشف notifications:scan، جاهز للبثّ.

كاش تجميعات لوحة القيادة

قراءات مُخزَّنة (مفاتيح مُصدَّرة)، flushCache() عند om:sync، وحالة الأسطول مُجمَّعة بـ SQL.

معالجة أخطاء API موحّدة

ResponseHelper::fromException (يخرِّط رموز الحالة، يسجّل 5xx، لا تسريب في الإنتاج) بدل ~132 التقاطاً.

حواجز سلامة البيانات

حارس إقفال أحداث الورشة (كلفة/مورّد/تاريخ رجوع)، تعاقب الحالة التشغيلية، وتنبيهات تسرّب مالي.

خارطة الطريق — المراحل القادمة

6 مراحل
المرحلة 1 — تسليم محكم

بوابة جاهزية (9 فحوص) + قائمة صور إلزامية (16 بنداً) عند التسليم/الاستلام + توقيع العميل/OTP.

المرحلة 2 — تقييم الأضرار والحوادث

نموذج تقييم أضرار مُهيكل (مسؤولية/تقدير/قرار) + تصنيف الحوادث التسعة أثناء الإيجار.

المرحلة 2.5 — حماية العميل والوديعة

سجل الوديعة + حجز المخالفات/السالك بعد الإرجاع + وسم مخاطر العميل (طبقة حماية النقد).

المرحلة 3 — جسر توجيه الكراج

ربط محرك تقييم الكراجات بمسار التوزيع + التقاط سبب التجاوز + إكمال المعايير الثمانية.

المرحلة 4 — المالية ومصفوفة الموافقات

عرض سعر ثم موافقة متدرّجة حسب المبلغ (مشرف/مدير/GM) + تنبيه البيع/الاستبدال.

المرحلة 5 — ضمان الجودة واختبار القيادة

قائمة فحص QA إلزامية لكل تذكرة + اختبار قيادة مشروط + تنبيهات 7/14 يوماً والجاهزية.
